What can actually run on a Pixel 8 without cloud?

Gemini Nano on Pixel 8

Google ships Gemini Nano on Pixel 8, but with significant limitations:

  • Model size: 1.8B-3.25B parameters, 4-bit quantized
  • Input: Text only (no images, no audio) on Pixel 8. Pixel 9+ gets multimodal.
  • Capabilities: Smart replies in messaging, audio transcript summaries (max ~15 min)
  • Not enabled by default on Pixel 8 (hidden in AI Core settings)
  • Works offline -- no data sent to Google servers
  • Access: Through Android AICore system service. Requires GMS (which we don't use).

What this means for us

We can't use Gemini Nano because it requires Google Mobile Services. But the Tensor G3 chip in Pixel 8 has a TPU (Tensor Processing Unit) that CAN run other models. Our options for local inference:

Practical plan

  • Phase 1: Cloud only (Claude API). No local inference. Simple and reliable.
  • Phase 2: Add LiteRT-LM with Gemma 1B (720MB) for local intent routing on GPU. Cloud for generation.
  • Phase 3: Add Phi-4 Mini (2.5GB) for local app generation on GPU. Cloud as fallback for complex apps.
  • Phase 4+: Fully offline capable. Local embeddings for search. See Framework Decision for details.

Apple's Foundation Models

Apple opened on-device models to developers via the Foundation Models framework at WWDC 2025. Runs on Apple Silicon with Neural Engine. Supports text generation, entity extraction, and classification.

Relevance: Validates that on-device LLMs are becoming a platform feature. Both Google and Apple ship them. Our differentiator isn't having local AI -- it's using AI to CREATE apps, not just assist in existing ones.

WebView Performance Reality

Research and benchmarks on WebView vs native performance:

  • For most apps (lists, forms, data display): Performance difference is negligible. Users can't tell.
  • For complex animations/games: Native has an advantage. WebGL/WebGPU narrows the gap.
  • JavaScript execution: Chrome is significantly faster than Android WebView for some metrics. We use Chromium Content Shell which matches Chrome performance.
  • Android WebView fragmentation: 14+ OS versions, 30+ WebView versions in the wild. We control both, so this doesn't apply.
  • Energy consumption: Research shows JavaScript can match or beat Java for many workloads in energy efficiency.

Bottom line: For the kinds of apps AI generates (trackers, dashboards, forms, tools), WebView performance is not a problem. For 3D games or AR, native wins -- but those aren't our use case.
