Glossary

Every term used in this knowledge base, defined in one place

AOSP
Android Open Source Project. The open-source code that Android is built from. Google publishes it; anyone can modify and build their own OS from it. We use it via GrapheneOS. More
ART
Android Runtime. The Java/Kotlin virtual machine that runs Android system services. In our OS, ART runs system services only — no third-party apps use it. Invisible to the user.
Blink
The rendering engine inside Chromium/Vanadium. Parses HTML, lays out CSS, paints pixels. Part of our TWA runtime. More
Capability Broker
Our security boundary. A Java service that sits between web app JavaScript and Android system APIs. Every hardware/system call goes through it: checks manifest, checks user permission, enforces, logs to audit trail. API docs / Tier system
Capability Tier
One of 5 levels of system access (Tier 0 = automatic, Tier 4 = kernel-adjacent). Each tier requires increasing levels of user approval. Full breakdown
CSP
Content Security Policy. HTTP headers that restrict what a web page can do (e.g., block eval(), block external scripts). We enforce strict CSP on all generated TWAs.
GMS
Google Mobile Services. Google's proprietary apps and APIs (Play Store, Play Services, Firebase, Maps API, FCM push). We don't use GMS. GrapheneOS ships without it.
GrapheneOS
Privacy-focused mobile OS based on AOSP, targeting Pixel phones. Our base distribution. Provides Vanadium, hardened memory allocator, hardened kernel, per-app network/sensor permissions, and monthly security patches. Full details
HAL
Hardware Abstraction Layer. Binary interface between Android framework and hardware drivers. Each hardware component (camera, BLE, WiFi, GPS, GPU) has a HAL. These are vendor-provided binaries we cannot modify. Module map
Halium
Compatibility layer that bridges Android HAL drivers into a standard Linux userspace. Used by Ubuntu Touch and Droidian. No Pixel 8 port exists. Research
LTO
Link-Time Optimization. Compiler technique that optimizes across compilation units at link time. GrapheneOS mandates LTO for security (enables CFI). Very memory-intensive — needs 32GB+ RAM to build.
MTE
Memory Tagging Extension. ARM hardware feature on Tensor G3 that tags memory allocations to detect use-after-free and buffer overflow bugs at runtime. GrapheneOS enables this.
Pixel 8 (shiba)
Our target hardware. Google Pixel 8, codename "shiba." Tensor G3 SoC with TPU for on-device AI. Unlockable bootloader for custom OS flashing.
SurfaceFlinger
Android's display compositor. Takes rendered frames from all apps and composites them onto the screen. Native C++ daemon. Required for any display output.
Tensor G3
Google's custom SoC in Pixel 8. Includes CPU, GPU (Imagination), TPU (for AI inference), ISP (image signal processor), and 5G modem. All drivers are Android-specific.
TWA
Trusted Web App. Our app format. A signed HTML/CSS/JS bundle with a capability manifest, version history, audit trail, and sandboxed storage. The ONLY app format on AIPhone OS. Not the same as Android's "Trusted Web Activity." Full spec
UnifiedPush
Open protocol for push notifications without Google FCM. Our planned replacement for Google's push notification infrastructure. App lifecycle
V8
Google's JavaScript engine. Compiles JS to native machine code. Part of Chromium/Vanadium. Executes all TWA app code. Runtime decision
Vanadium
GrapheneOS's hardened fork of Chromium. Our TWA runtime engine. Includes V8 (JS), Blink (rendering), Skia (graphics), WebGPU. Pre-built and maintained by the GrapheneOS team. Details
WebGPU
Modern web API for GPU compute and rendering. Successor to WebGL. Supported in Chromium/Vanadium on Android. Potential path for on-device AI inference in the browser runtime. AI research
Zygote
Android process that pre-loads common framework classes and forks to create new app processes. All Android apps (including our WebView) start as Zygote forks. GrapheneOS optionally replaces this with exec spawning for better isolation.
