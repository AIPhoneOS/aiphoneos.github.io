App Generation Pipeline

How "make me a workout tracker" becomes a running app

Pipeline

User Prompt
  |  "Make me a spending tracker with receipt photos"
  v
Intent Classification
  |  Is this "create app" / "modify app" / "question" / "action"?
  v
Clarification (if needed)
  |  "Should it categorize expenses automatically?" (max 1 question)
  v
AI App Generator (Claude Sonnet)
  |  System prompt with TWA API docs + design constraints
  |  Output: { manifest.json, index.html }
  v
Security Analysis
  |  CSP compliance, deny-list scan, capability audit
  |  PASS or REGENERATE
  v
Permission Approval UI
  |  "This app needs: storage, camera" — user approves
  v
TWA Package Creation
  |  Sign, store, create v1 in history
  v
App Installed & Running

AI System Prompt (Key Constraints)

  • Generate a single self-contained HTML file with inline CSS and JS
  • Dark theme matching OS design language (#1c1c1e bg, #fff text, #0a84ff accent)
  • Mobile-first responsive layout (390px phone, up to 1024px tablet)
  • Touch-friendly: 44px minimum tap targets
  • Use window.aiphone.* APIs — no raw browser APIs for capabilities
  • Declare all required capabilities in manifest
  • Data stays local by default (local-only network policy)
  • No eval(), no dynamic external script loading

Failure Handling

FailureResponse
Network unavailable"Cloud AI needed. Connect or try a simpler request."
Generation timeoutRetry with simplified prompt
Token limit exceededSplit into smaller app + suggest enhancements
Static analysis failsAuto-regenerate with tighter constraints (max 2 retries)
Generated app crashesUser can rollback, ask AI to fix, or report
Ambiguous requestAI asks one clarifying question, sets sensible defaults for the rest

Cost Management

  • Each generation has a token budget (visible to user in settings)
  • Simple apps: ~2K tokens output (~$0.01)
  • Complex apps: ~8K tokens output (~$0.05)
  • Modifications: typically cheaper than full generation
  • Users set a monthly AI budget; OS warns before exceeding
  • Offline intent routing (Phase 3+) avoids cloud costs for simple interactions

Validation Before Install

  1. CSP check — inject strict Content-Security-Policy headers
  2. Pattern deny-list — reject eval(), Function(), document.write(), external script URLs
  3. Capability audit — flag any aiphone.* calls not declared in manifest
  4. Size check — reject bundles over limit (default: 2MB)
  5. Render test — headless render to catch obvious layout/crash issues
