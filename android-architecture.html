Data Flow: "Make me a timer"

When the user says "make me a timer," here's how it flows through the stack:

  1. AIPhoneHome (WebView) receives the text input
  2. AI Service sends the prompt to Claude API (cloud)
  3. Claude generates HTML/CSS/JS for a timer app
  4. Capability Broker performs static analysis on the generated code
  5. User approves permissions (storage, notifications)
  6. App is installed as a TWA in the local app store
  7. User taps to open — a new Vanadium WebView process loads the HTML
  8. Timer uses aiphone.notifications.schedule() which goes through the Capability Broker
  9. Broker calls AlarmManager (Android Framework) to schedule the alarm
  10. AlarmManager uses Power HAL to set a kernel wakeup timer
  11. Kernel wakes the Tensor G3 CPU at the scheduled time
  12. NotificationManager shows the notification via SurfaceFlinger on the OLED display

Data Flow: Camera Access

When a generated app calls aiphone.camera.capture():

  1. JavaScript in the TWA's WebView calls window.aiphone.camera.capture()
  2. Capability Broker checks: does this app have camera permission? Is it user-approved?
  3. If yes: Broker calls CameraManager (Android Framework)
  4. CameraManager talks to CameraService (native C++ daemon)
  5. CameraService talks to Camera HAL (vendor binary)
  6. Camera HAL controls the Tensor G3 ISP (image signal processor) and camera sensor
  7. Photo data flows back up the stack to the WebView as a Blob
  8. Audit log records: app X used camera at time Y, result: success, size: Z bytes
