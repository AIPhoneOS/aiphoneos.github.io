Our Build Process (GrapheneOS-based)

# 1. Sync GrapheneOS source (~118GB, 2-4 hours)
repo init -u https://github.com/GrapheneOS/platform_manifest.git \
  -b 16-qpr2
repo sync -c -j$(nproc) --no-tags --force-sync

# 2. Apply our overlay (AIPhoneHome + device config)
./overlay/apply-overlay.sh

# 3. Set up build environment
source build/envsetup.sh
lunch shiba

# 4. Build
m -j$(nproc)

# 5. Flash to Pixel 8
# Boot to bootloader: adb reboot bootloader
fastboot flashall -w

Raw AOSP Build (for reference)

# If building from raw AOSP instead of GrapheneOS:
repo init -u https://android.googlesource.com/platform/manifest \
  -b android-latest-release
repo sync -c -j$(nproc) --no-tags
# Extract vendor blobs from factory image
# Use android-prepare-vendor to extract
source build/envsetup.sh
lunch aosp_shiba-userdebug
m -j$(nproc)

What We Can Strip

AOSP build is configured via PRODUCT_PACKAGES in product makefiles. Removing apps is straightforward:

# In our device/aiphone/product.mk:
PRODUCT_PACKAGES += \
  -Launcher3 \
  -Launcher3QuickStep \
  -Calendar \
  -Calculator \
  -Camera2 \
  -Contacts \
  -DeskClock \
  -Email \
  -Gallery2 \
  -Music \
  -QuickSearchBox

# Add our system app
PRODUCT_PACKAGES += \
  AIPhoneHome

What We CANNOT Easily Strip

  • Android Framework (frameworks/base): Monolithic. SurfaceFlinger, WindowManager, ActivityManager, PackageManager are all interdependent. Removing one breaks others.
  • SystemUI: Handles status bar, navigation, volume, power menu, incoming calls. We need to KEEP this as a safety net but can customize it.
  • ART runtime: System services are written in Java and run on ART. Can't remove ART without rewriting system services in native code.
  • Zygote: The process that spawns all Android apps, including system services. Required.

Practical "Minimal" AOSP

The realistic minimum is:

  • Full AOSP system with all framework components (they're required)
  • All stock apps removed via PRODUCT_PACKAGES exclusions
  • Our AIPhoneHome added as a privileged system app
  • AIPhoneHome registered as the default HOME activity
  • SystemUI retained for critical system events
  • Result: phone boots to our AI chat, Android framework runs invisibly

How GrapheneOS Does It

GrapheneOS is the best example of a stripped AOSP build:

  • Removes all Google apps and services
  • Keeps the full Android framework (required for system services)
  • Adds hardened memory allocator, network permissions, sensor permissions
  • Sandboxed Google Play compatibility layer (optional, runs as unprivileged app)
  • Supports Pixel 4 through Pixel 9 series
  • Published detailed build documentation

Key lesson: GrapheneOS proves that a solo-ish team can maintain a custom AOSP build for Pixel devices. They've been doing it for years. We can learn from their build process.

Android Kiosk / Device Owner Mode

Android has built-in support for locking a device to a single app:

  • Lock Task Mode: Pins the device to one app. No home button, no recents, no notifications (unless allowlisted).
  • Device Owner Mode: Full device management. Can set kiosk policies, allowlist apps, control updates.
  • Setup: DevicePolicyManager.setLockTaskPackages() to allowlist our app, then Activity.startLockTask()
  • Since Android 9: Can start any activity in lock task mode via ActivityOptions.setLockTaskEnabled()

This is useful for Phase 1: before we build a full AOSP image, we can use kiosk mode on stock Android to simulate the "boot to our UI" experience for testing.

Build Environment

  • OS: Linux required (Ubuntu 22.04 recommended). macOS not supported. Use Docker.
  • RAM: 16GB minimum, 32GB recommended. We have 64GB.
  • Disk: 300GB+ needed. We have 1TB free.
  • CPU: More cores = faster build. x86_64 required.
  • Java: JDK 17 required. We have it.
  • Docker image: Already created at build/Dockerfile
