AI Architecture

The intelligence layer of the OS

The AI is the orchestration and creation layer, not the kernel or security layer.

What AI Does

See App Generation for the full pipeline, and Broker API for the aiphone.ai.* interface apps use.

  • App generation from natural language
  • App modification and updates
  • Intent classification and routing
  • Contextual suggestions and dashboards
  • In-app AI access (via aiphone.ai.*)
  • Workflow automation across approved apps
  • Explanations of actions and permissions

What AI Cannot Own

  • Secure boot or verified boot
  • Process isolation or sandboxing enforcement
  • Encryption key custody
  • Permission enforcement (Capability Broker handles this deterministically)
  • Payment authorization without explicit user confirmation
  • Silent expansion of permissions
  • Kernel scheduling or radio/telephony safety

Performance & Battery

  • AI responds to explicit user intents — not constant background activity
  • System job queue with compute/token/battery budgets per task
  • Generated apps run deterministic code — AI is not called to render UI
  • Single OS-level AI scheduler (not dozens of uncoordinated app agents)
  • Local models for low-latency private tasks when hardware permits
  • Cloud models only when allowed by user and connectivity
  • All AI actions visible in audit trail

Pluggable Architecture

The AI layer is provider-agnostic. Claude is the default, but users can configure alternatives. The system defines interfaces, not implementations:

  • AppGenerator — takes prompt + context, returns HTML/manifest
  • IntentRouter — takes user text, returns action classification
  • QueryHandler — handles in-app AI queries
  • Transcriber — speech to text
  • Embedder — text to vectors
