What Fits in 4GB of Available RAM

With the OS using ~4GB, we have ~4GB for a model. Q4_K_M quantization (4-bit, ~95% quality) is the standard for mobile in 2026.

Phi-4 Mini (3.8B) — RECOMMENDED
Size: ~2.5GB Params: 3.8B Quant: Q4_K_M

Smartest sub-4B model in 2026. Outperforms Gemma 3 4B and Llama 3.2 3B on reasoning tasks despite smaller size. Strong at code generation — critical for our app generation pipeline. From Microsoft.

Gemma 3 1B — FAST FALLBACK
Size: ~720MB Params: 1B Quant: Q4_K_M

Tiny and fast. Good for intent classification ("is this a create/modify/question request?"), not good enough for app generation. From Google, Apache 2.0 license.

Qwen 2.5 1.5B — MULTILINGUAL
Size: ~1.1GB Params: 1.5B Quant: Q4_K_M

Best multilingual small model. If the OS needs to work in languages beyond English, this is the intent router. From Alibaba, Apache 2.0.

Llama 3.2 3B
Size: ~2.1GB Params: 3B Quant: Q4_K_M

Solid general purpose. Good instruction following. From Meta, Llama license. Outperformed by Phi-4 Mini at similar size.

Inference Runtime: llama.cpp

llama.cpp is the clear choice for our on-device inference engine:

  • Pure C/C++ — no Python, no framework overhead. Compiles to a single binary.
  • GGUF model format — the standard quantized format. Every model above ships in GGUF.
  • CPU inference with ARM NEON — reliable, works on all ARM devices including Pixel 8.
  • Vulkan GPU backend — can offload layers to GPU. Performance varies on Imagination GPU but worth enabling.
  • NNAPI delegation — experimental support for Android's Neural Networks API, which can route to Tensor G3 TPU.
  • Memory-mapped model loading — model file is mmap'd, not loaded into RAM. OS manages paging.
  • MIT license — no licensing issues.

Two-Model Strategy

We run TWO models, not one. Different jobs need different sizes:

Model A: Intent Router (always loaded)

Gemma 3 1B — 720MB in RAM, instant response

Classifies every user input: "is this a request to create an app, modify an app, ask a question, or perform a system action?" Does NOT generate apps. Just routes.

This model stays loaded in memory permanently. 720MB is small enough to coexist with the OS and an active app.

Model B: App Generator (loaded on demand)

Phi-4 Mini 3.8B — 2.5GB, loaded when user asks to create/modify an app

Generates actual HTML/CSS/JS code. Loaded into memory when a generation request comes in, unloaded after. For complex apps, falls back to cloud (Claude API) for higher quality.

When this model is loaded, the intent router may be swapped out temporarily. That's OK — generation takes 10-30 seconds, then we swap back.

System Architecture: AI Service

The local LLM is managed by a system-level Android service called AiService. This is the control module.

AiService — The AI Control Module

AiService (Android Foreground Service)
├── ModelManager
│   ├── load(modelPath, backend)     // mmap GGUF, init llama.cpp
│   ├── unload()                      // free memory
│   ├── isLoaded()                    // check state
│   └── getMemoryUsage()             // monitor RAM
│
├── IntentRouter (Gemma 1B — always loaded)
│   ├── classify(userText)            // → create | modify | query | action
│   └── extractEntities(text)         // → app name, parameters
│
├── AppGenerator
│   ├── generate(prompt, context)     // → HTML/CSS/JS
│   │   ├── tryLocal(Phi-4 Mini)      // attempt on-device first
│   │   └── fallbackCloud(Claude)     // if local fails or times out
│   ├── modify(existingHtml, prompt)  // update existing app
│   └── validate(html)                // static analysis before install
│
├── QueryHandler
│   ├── ask(prompt)                   // general questions
│   ├── summarize(text)               // text summarization
│   ├── classify(text, categories)    // classification
│   └── extract(text, schema)         // structured extraction
│
└── InferenceEngine (llama.cpp wrapper)
    ├── init(ggufPath, params)        // load model
    ├── complete(prompt, maxTokens)   // generate text
    ├── tokenize(text)                // count tokens
    ├── setBackend(cpu|vulkan|nnapi)  // choose compute
    └── abort()                       // cancel generation

1
User types/speaks "make me a timer" in AIPhoneHome WebView
2
WebView JS calls native bridge → AiService receives the text
3
IntentRouter (Gemma 1B, already loaded) classifies: "create app" with entity "timer"
~200ms, on-device, no network
4

~2-3 seconds to load from storage via mmap

~10-20 seconds to generate ~2000 tokens of HTML/CSS/JS at ~15 t/s

~100ms
7
ModelManager unloads Phi-4 Mini, reloads Gemma 1B for intent routing
~1 second
8

Total: ~15-25 seconds fully on-device, zero network

How llama.cpp Integrates Into the OS

llama.cpp compiles to a shared library (libllama.so) that lives in the system partition:

/system/lib64/libllama.so          — llama.cpp inference engine
/system/lib64/libggml.so           — GGML tensor library
/data/local/aiphone/models/
  ├── gemma-3-1b-q4_k_m.gguf      — intent router (720MB)
  └── phi-4-mini-q4_k_m.gguf      — app generator (2.5GB)

AiService (Java) → JNI → libllama.so → CPU/Vulkan/NNAPI → hardware

Battery Impact

  • Intent routing (Gemma 1B): ~200ms per classification. Negligible battery impact. Equivalent to a web page load.
  • App generation (Phi-4 Mini): ~15-25 seconds of full CPU load. Roughly equivalent to taking a 15-second video. Maybe 0.5-1% battery per generation.
  • Idle: Models are mmap'd, not actively in RAM when unused. Zero battery drain when not generating.
  • Thermal: Continuous generation for >60 seconds triggers thermal throttling. The OS should queue requests, not allow concurrent generation.

Open Questions

  • Vulkan performance on Imagination GPU: needs real-world benchmarking on Pixel 8. May be slower than CPU.
  • NNAPI + TPU delegation: can llama.cpp delegate specific ops to the Tensor G3 TPU? Experimental, needs testing.
  • Model quality for code generation: can Phi-4 Mini at 4-bit quantization generate correct, functional HTML/CSS/JS consistently? Needs systematic testing.
  • Hot-swap latency: how fast can we unload Phi-4 Mini and reload Gemma 1B? Target: under 2 seconds.
  • WebGPU inference in Vanadium: could we run inference inside the browser runtime via WebGPU instead of a system service? Worth exploring in Phase 4+.
