Inference Runtime

How LLM inference runs on Pixel 8 without touching the CPU

Core Principle

CPU is for the user. GPU/TPU is for the LLM. They never compete. The UI stays at 120fps while the LLM generates in the background on separate hardware.

Why LiteRT-LM

See Framework Decision for the full comparison. Summary:

  • 52 t/s on Android GPU via OpenCL — 3-4x faster than llama.cpp Vulkan
  • Built for mobile GPU sharing — coexists with UI rendering, unlike desktop-oriented Vulkan backends
  • KV cache, sessions, multi-turn — all managed by the framework, not by us
  • Supports Gemma, Phi-4, Llama, Qwen — all our candidate models
  • No GMS required — runs on GrapheneOS
  • Made by Google for Tensor hardware — optimized for the exact GPU/NPU in Pixel 8

Compute Backends on Pixel 8

OpenCL GPU — Primary

  • All LLM inference runs here. Separate hardware from CPU — UI stays smooth.
  • Pixel 8: Imagination BXE-9-256 GPU with OpenCL support.
  • LiteRT-LM uses OpenCL compute kernels optimized for transformer operations.
  • 52 t/s decode speed benchmarked by Google on Android GPU.
  • Designed to share GPU with Android's rendering pipeline without causing jank.

NPU/TPU — Secondary Accelerator

  • LiteRT-LM has built-in NPU support for Tensor G3's edge TPU.
  • Routes supported operations (matmul, linear layers) to dedicated ML hardware.
  • Can work alongside GPU — GPU handles attention, NPU handles linear projections.
  • Status: Built into LiteRT-LM. Needs benchmarking to measure actual speedup on Pixel 8.

CPU — Last Resort Only

  • NOT used for inference by default. CPU runs the UI, Android framework, WebView.
  • LiteRT-LM has a CPU backend as fallback if GPU/NPU both fail.
  • If we ever fall back to CPU: this is a bug, not a feature. Log it and investigate.

Memory Management

  • LiteRT-LM handles model loading — optimized for mobile memory constraints.
  • KV cache: Managed by LiteRT-LM. Session state persisted across turns. Compressed under memory pressure.
  • Model switching: LiteRT-LM supports loading/unloading models. Switch from Phi-4 Mini back to Gemma 1B for intent routing.
  • OOM protection: AiService monitors memory pressure and proactively unloads the generation model if RAM drops below threshold.

LiteRT-LM Integration Code

// InferenceEngine.java — LiteRT-LM wrapper
import com.google.ai.edge.litert.lm.LlmInference;
import com.google.ai.edge.litert.lm.LlmInference.LlmInferenceOptions;

public class InferenceEngine {
    private LlmInference inference;

    public void load(String modelDir, boolean useGpu) {
        LlmInferenceOptions options = LlmInferenceOptions.builder()
            .setModelPath(modelDir)
            .setMaxTokens(4096)
            .setPreferredBackend(useGpu
                ? LlmInferenceOptions.Backend.GPU   // OpenCL
                : LlmInferenceOptions.Backend.CPU)  // fallback only
            .build();
        inference = LlmInference.createFromOptions(options);
    }

    public String generate(String prompt, int maxTokens) {
        return inference.generateResponse(prompt);
    }

    public void generateStreaming(String prompt, Consumer<String> onToken) {
        inference.generateResponseAsync(prompt, onToken::accept);
    }

    public void unload() {
        if (inference != null) { inference.close(); inference = null; }
    }
}
