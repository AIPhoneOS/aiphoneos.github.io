Why llama.cpp

  • Ecosystem: GGUF is the universal model format. Every model we evaluated ships in GGUF. No conversion needed.
  • Simplicity: Compiles to a single .so library. No Python runtime, no Java framework, no TensorFlow dependency.
  • Performance: Heavily optimized for ARM NEON (Pixel 8's CPU). Memory-mapped model loading avoids copying 2.5GB into RAM.
  • Active development: Most active open-source LLM inference project. New optimizations weekly.
  • License: MIT. No restrictions.
  • Proven on Android: PocketPal AI, Llama on Phone, and other apps already use llama.cpp via NDK.

Compute Backends on Pixel 8

CPU (ARM NEON) — Primary

  • Always works. No driver issues. Predictable performance.
  • Uses ARM NEON SIMD instructions for vectorized operations.
  • Pixel 8: 1x Cortex-X3 (3.0 GHz) + 4x A715 (2.6 GHz) + 4x A510 (1.8 GHz)
  • Expected: ~10-15 tokens/sec for 3.8B model, ~30-40 for 1B model.
  • Thermal throttling after 60-90 sec continuous generation.

Vulkan GPU — Experimental

  • Pixel 8 has Imagination BXE-9-256 GPU with Vulkan 1.3 support.
  • llama.cpp Vulkan backend uses compute shaders for matrix operations.
  • Performance is hit-or-miss on Imagination GPUs. Adreno and Mali have more testing.
  • Potential speedup: offload some transformer layers to GPU while CPU handles the rest.
  • Status: Needs benchmarking on Pixel 8 before committing. May be slower than CPU.

NNAPI → TPU — Future

  • Android's Neural Networks API can delegate operations to the Tensor G3 edge TPU.
  • llama.cpp has experimental NNAPI support but it's limited to specific operations.
  • The TPU is optimized for specific op patterns (conv, matmul). Not all transformer ops are supported.
  • Status: Phase 3+ exploration. Don't depend on this working initially.

Memory Management

  • mmap loading: Model files are memory-mapped, not read into RAM. The OS pages in only what's needed. This means a 2.5GB model doesn't use 2.5GB of physical RAM immediately.
  • KV cache: The key-value cache for context grows during generation. For 2K token context on a 3.8B model: ~200MB additional RAM.
  • Hot-swap: When switching from Phi-4 Mini back to Gemma 1B, we munmap() the large model and mmap the small one. Target: under 2 seconds.
  • OOM protection: Android's low-memory killer will target our model before killing user apps. AiService monitors memory pressure and proactively unloads if RAM drops below 500MB free.

Building llama.cpp for Android

# Cross-compile llama.cpp for Android ARM64 with Vulkan
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp

# Using Android NDK
cmake -B build-android \
  -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-33 \
  -DGGML_VULKAN=ON \
  -DGGML_NATIVE=OFF \
  -DBUILD_SHARED_LIBS=ON

cmake --build build-android --config Release

# Output: build-android/src/libllama.so + build-android/ggml/src/libggml.so
# Copy to: system/lib64/ in AOSP overlay

JNI Bridge (Java ↔ C++)

// InferenceEngine.java — JNI wrapper for llama.cpp
public class InferenceEngine {
    static { System.loadLibrary("llama"); }

    // Native methods — implemented in C++
    private native long nativeInit(String modelPath, int nThreads, boolean useVulkan);
    private native String nativeComplete(long ctx, String prompt, int maxTokens);
    private native int nativeTokenCount(long ctx, String text);
    private native void nativeAbort(long ctx);
    private native void nativeFree(long ctx);

    private long ctx = 0;

    public void load(String modelPath, boolean useGpu) {
        ctx = nativeInit(modelPath, 4, useGpu);  // 4 threads
    }

    public String complete(String prompt, int maxTokens) {
        if (ctx == 0) throw new IllegalStateException("Model not loaded");
        return nativeComplete(ctx, prompt, maxTokens);
    }

    public void unload() {
        if (ctx != 0) { nativeFree(ctx); ctx = 0; }
    }
}
