Why Linux Kernel

Not because it's the best. Because it's the only one with phone hardware drivers.

The Question

If we're building a new OS from scratch, should we start with the best kernel for the job? Could a microkernel be more secure? Could something custom be lighter?

The Answer

Linux is the only kernel that can talk to phone hardware. Every phone chipset vendor (Qualcomm, MediaTek, Samsung LSI, Google Tensor) ships Linux drivers only. There is no alternative kernel that supports:

  • Cellular basebands (calls, SMS, data)
  • Mobile GPUs (Adreno, Mali, Imagination)
  • Camera ISPs (image signal processors)
  • Power management (big.LITTLE scheduling, thermal throttling)
  • Display controllers and touch controllers
  • NFC, Bluetooth/BLE, WiFi chipsets
  • Fingerprint sensors, face unlock hardware

The Real Decision

Linux is a pragmatic lock-in, not an aspirational choice. The real decision isn't the kernel. It's what we put above it:

  • The AI interaction model
  • The web app runtime
  • The Capability Broker
  • The app generation pipeline
  • The permission and audit system

Linux handles hardware. Our innovation is everything above it.
