Why No Native Apps

Web apps only. No Android APKs. No compatibility layer. A clean break.

The Decision

AIPhone OS runs only web apps (TWAs). No Android APK support. No compatibility shim. No "run your existing apps" promise.

This is the boldest and most controversial decision in the project. Here's why it's right.

The Challenge

"Name one app that can't be a web app that users can't live without."

Why This Is the Moat

Apple and Google will never give web apps deep system access. Here's why:

  • App Store revenue: Apple takes 30% of native app purchases. Web apps bypass the store entirely. Apple has actively sabotaged PWA support on iOS to protect this revenue.
  • Developer lock-in: Swift and Kotlin skills don't transfer across platforms. Web skills do. If web apps worked as well as native, developers would stop writing platform-specific code.
  • Platform switching cost: If all your apps are web apps, switching from iPhone to Android (or to AIPhone OS) costs nothing. Apple and Google benefit from the switching cost that native apps create.

AIPhone OS has no app store revenue to protect. We want web apps to be more powerful than native. That's the product, not a threat to it.

What About Firefox OS?

Firefox OS (2012-2015) tried web-only and failed. But it failed for specific reasons:

  • Web apps had no more capability than a browser tab -- no deep hardware access
  • Targeted low-end hardware in emerging markets -- poor performance
  • No AI -- users still had to find and install pre-built apps. No generation.
  • App ecosystem was thin -- developers had no reason to build for a niche platform

Every one of these problems has a different answer today:

  • Our TWAs get deeper access than native apps via the Capability Broker
  • We target flagship hardware (Pixel 8, Tensor G3)
  • AI generates apps -- the ecosystem bootstraps from day one
  • Apps are personal -- they don't need a marketplace to exist

The Risk

This is the biggest bet in the project. If users can't live without native-only capabilities (NFC payments, specific government apps), this OS cannot be a daily driver.

Mitigation: Start with the enthusiast/developer segment that accepts trade-offs. Monitor which native apps users actually miss. Phase 3+ evaluates a minimal Android compatibility shim if the evidence demands it. But the default position is: web apps are enough.
