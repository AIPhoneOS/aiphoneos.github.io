Founding Story

How this project started and what drives it

The One-Sentence Product

I want to talk to my phone about the app I need and it instantly magically has it.

Not "build an AI-native operating system for phones and tablets." Not "compete with iOS and Android." Not a 990-line architecture document. One sentence. Everything we build serves that sentence.

The Founder

Serge runs multiple web app platforms: FreeAppStore, ProAppStore, FreeGameStore, and others. He builds and operates the infrastructure for web-based app publishing and distribution.

From running these stores, he sees the bottleneck firsthand: the problem isn't distribution. The problem is creation. Users shouldn't need a developer to get the app they need. The app store model -- where developers predict needs and users search for approximations -- is fundamentally broken for personal, niche, and situation-specific tools.

The Diagnostic (May 2026)

During a rigorous product diagnostic (YC office hours style), the following was established:

Demand Reality

Honest assessment: zero external demand evidence. The founder is the primary and only user. No one has asked for this product. No one has paid for it. No one would notice if it disappeared.

However: the founder has real domain expertise from operating web app stores, and the core technology (LLM app generation) is proven in concept. The question is whether the OS is the right delivery vehicle.

Status Quo

The founder currently builds web app platforms using templates, AI-assisted development, and manual publishing workflows. Personal tool needs are met by coding them directly. The workaround is: build it yourself, or live without it.

The Defended Premise

When challenged on "no existing apps means no banking, no maps, no messaging," the founder pushed back:

"Name one app that can't be a web app that users can't live without."

The answer is shorter than expected:

  • NFC tap-to-pay -- requires Secure Element access
  • Government ID apps -- require certified secure enclaves
  • Platform push notifications (when app is killed) -- requires FCM/APNs integration

But banking? Web versions exist. Email? Web. Maps? Web. Social media? Web. Messaging? Web versions exist. Shopping, news, weather, music streaming? All have web versions. The list of apps that truly require native-only access is much shorter than the industry assumes.

This is a genuine insight that strengthens the web-only thesis. Apple and Google benefit from the perception that native is required. Often it isn't.

Why Not Validate Cheaply First?

Three approaches were considered:

  • A) Add AI generation to FreeAppStore -- cheapest, fastest, tests the core thesis on existing infrastructure
  • B) Android launcher app -- gets on real phones without OS work
  • C) Full OS -- the complete vision

The recommendation was A (validate cheaply). The founder chose C (build the OS). The compromise: run A in parallel as Phase 0 validation while building the OS.

What Was Noticed

Observations from the diagnostic session:

  • The founder's one-sentence product description ("talk to phone, get app") is clearer and more compelling than any architecture document. Every decision should serve that sentence.
  • When challenged on assumptions, the founder challenged back with real arguments. That's conviction, not compliance.
  • The domain expertise is real -- years of operating web app platforms, not a shower thought about phone OSes.
  • Choosing the hardest path (full OS) when the easiest path was recommended is either conviction or stubbornness. Building the product will reveal which.

The Assignment

Two things, in parallel:

  1. This week: Put a "Create App" button on FreeAppStore that takes a text prompt and generates a web app. Watch what people type. Watch what they do. (Phase 0 validation)
  2. This month: Get AOSP minimal building for Pixel 8. Boot to a custom home screen with AI chat. (Phase 1)

If Phase 0 shows nobody cares about AI-generated apps, the OS work stops early. If they love it, the OS gets built with real conviction.
